# 0.3.9 Private Lists Plan

## Overview

Add a `private` flag to lists, allowing users to exclude specific lists from sync operations. Private lists stay on the local device only.

## Goals

- Users can mark any list as private or shared
- Private lists never appear in sync data (push/pull)
- Polished, professional GUI with clear visual indicators
- Existing lists remain shared (no surprise behavior changes)

---

## Data Model Changes

### TodoList Model

```python
@dataclass
class TodoList:
    # ... existing fields ...
    deleted: bool = False
    private: bool = False  # NEW: Private lists excluded from sync

    def toggle_private(self) -> None:
        """Toggle private status."""
        self.private = not self.private
        self.mark_updated()
```

### Database Model

```python
class Database:
    def to_dict_for_sync(self) -> dict[str, Any]:
        """Convert to dictionary for sync, excluding private lists."""
        return {
            "schema_version": self.schema_version,
            "active_list_id": str(self.active_list_id) if self.active_list_id else None,
            "lists": {
                str(k): v.to_dict()
                for k, v in self.lists.items()
                if not v.private  # Filter out private lists
            },
        }
```

### Serialization

- `to_dict()` includes `private` field
- `from_dict()` reads `private` with default `False` for backward compatibility

## Database Schema Migration

### Schema Version

```python
SCHEMA_VERSION = 4  # Was 3
```

### Migration Function

```python
def _migrate_schema_3_to_4(self) -> None:
    """Migrate schema from version 3 to 4 (add private column)."""
    current_version = self.get_schema_version()
    if current_version >= 4:
        return

    cursor = self.connection.execute("PRAGMA table_info(lists)")
    columns = [row[1] for row in cursor.fetchall()]

    if "private" not in columns:
        self.connection.execute(
            "ALTER TABLE lists ADD COLUMN private INTEGER NOT NULL DEFAULT 0"
        )

    self.set_schema_version(4)
```

### Migration Behavior

- Runs automatically on app startup
- Adds `private` column with default value 0 (shared)
- Existing lists remain shared
- No user interaction required

### Main Window Integration

```python
# Menu action
self.toggle_private_action = QAction("Toggle &Private", self)
self.toggle_private_action.setShortcut("Ctrl+Shift+P")
self.toggle_private_action.triggered.connect(self._on_toggle_private)

# Handler
def _on_toggle_private(self) -> None:
    active_list = self._database.active_list
    if active_list is None:
        return

    active_list.toggle_private()
    self._save_database()
    self._refresh_ui()

    status = "private (won't sync)" if active_list.private else "shared"
    self.status_bar_widget.show_message(
        f'List "{active_list.name}" is now {status}', 3000
    )
```

| Scenario | Handling |

| Active list made private | Still visible locally, just won't sync |
| Schema migration | Existing lists get `private=0` (shared) - no surprises |
| Backward compatibility | Old data without `private` field defaults to `False` |
