# v0.3.11 Release Overview

v0.3.11 is the most significant feature release since the P2P sync layer. It brings four desktop features (tags, keyboard shortcuts, Pomodoro timer, CalDAV import/export) and the critical Web UI milestone that opens the door to mobile access and the project's long-term vision.

## What This Release Accomplishes

The desktop app becomes feature-complete for daily use, and for the first time, users can access their todos from any device on the same network via a mobile-optimized web interface. This is the minimum viable "use it from your phone" moment described in the strategic roadmap.

## Phases

### Phase 1: Tags

Lightweight cross-list categorization via free-form text tags on items (e.g., `@work`, `@errands`, `@quick`). Tags add a cross-cutting organizational dimension without the overhead of nested projects or folders.

**Why first:** Tags add a new field to the data model (`tags: list[str]`). All subsequent phases (CalDAV export, Web UI) need to be aware of this field. Better to stabilize the model early.

**Scope:**
- `tags` field on `TodoItem`, stored as JSON array in SQLite TEXT column (schema v9)
- Tag input in AddTodoDialog, colored tag chips in item display
- Tag filter in SearchFilterWidget
- `EditTagsCommand` for undo/redo
- Sync-compatible via existing `to_dict()`/`from_dict()` with `.get()` defaults

### Phase 2: Keyboard Shortcuts

Comprehensive keyboard-driven workflow beyond the existing Ctrl+Z/Y and Ctrl+Shift+P shortcuts. Makes the native Qt app feel fast and intentional.

**Why second:** Pure desktop feature, no schema changes, no new dependencies. Quick win that can ship independently.

**Scope:**
- Table navigation: arrow keys, Enter to toggle, Delete to remove, E to edit
- List switching: Ctrl+1..9 for position, Ctrl+Left/Right to cycle
- Global: Ctrl+N (new item), Ctrl+Shift+N (new list), Ctrl+F (search), Escape (clear)
- Help dialog (F1) listing all shortcuts
- Configurable bindings deferred to future release

### Phase 3: Pomodoro / Focus Timer

A lightweight timer that pairs with the active todo item. Enables focused work sessions with configurable work/break intervals and automatic time tracking.

**Why third:** Standalone widget with its own schema change (`time_spent` field, schema v10). Self-contained — doesn't affect other features.

**Scope:** See [pomodoro-design.md](pomodoro-design.md) for detailed design.

### Phase 4: CalDAV Import/Export

Interoperability with the calendar and todo ecosystem via iCalendar VTODO format. Users can export lists as `.ics` files and import `.ics` files from other apps.

**Why fourth:** Depends on tags (Phase 1) for complete CATEGORIES mapping. New dependency (`icalendar`). File-based I/O that doesn't affect the running app's state model.

**Scope:** See [caldav-interop.md](caldav-interop.md) for detailed design.

### Phase 5: Web UI — Phase 1 (Embedded Server + REST API)

An embedded aiohttp web server that serves a mobile-optimized single-page app. This is the absolute requirement for v0.3.11 and the most architecturally significant addition since P2P sync.

**Why fifth:** The Web UI exposes the full data model. Tags, time tracking, and all other fields should be stable before building the API and frontend that presents them.

**Scope:** See [web-ui-architecture.md](web-ui-architecture.md) for detailed design.

### Phase 6: Web UI — Phase 2 (PWA Offline)

Progressive Web App enhancements: service worker for offline caching, web app manifest for "Add to Home Screen", and an offline edit queue that syncs when connectivity is restored.

**Why sixth:** Builds directly on Phase 5 infrastructure. Only makes sense after the base Web UI is working and tested.

**Scope:** See [pwa-mobile-strategy.md](pwa-mobile-strategy.md) for detailed design.

## Dependency Chain

```
Phase 1 (Tags) ──→ Phase 4 (CalDAV needs tags)
                └─→ Phase 5 (Web UI exposes tags)

Phase 3 (Pomodoro) ──→ Phase 5 (Web UI exposes time_spent)

Phase 5 (Web UI) ──→ Phase 6 (PWA builds on Web UI)

Phase 2 (Shortcuts) ── independent, no downstream deps
```

Phases 1, 2, and 3 are independent of each other and could theoretically be done in any order, but the ordering chosen minimizes rework: model changes first (1), then pure UI (2), then new widget + model (3), then I/O (4), then the big integration (5-6).

## Schema Migration Path

| Version | Phase | Column Added | Type |
|---------|-------|--------------|------|
| v8 (current) | — | `due_time` | TEXT |
| v9 | Phase 1 (Tags) | `tags` | TEXT (JSON array) |
| v10 | Phase 3 (Pomodoro) | `time_spent` | INTEGER |

Each migration follows the established pattern: check version, check column existence with `PRAGMA table_info`, `ALTER TABLE`, update version. All migrations are backward-compatible — older app versions simply ignore unknown columns.

## New Dependencies

| Package | Version | Phase | Purpose |
|---------|---------|-------|---------|
| `icalendar` | >=6.0 | Phase 4 | CalDAV import/export |
| `aiohttp` | >=3.9 | Phase 5 | Embedded web server |

Both are pure Python, well-maintained, cross-platform, and have no system-level dependencies. `aiohttp` was chosen over FastAPI specifically because it runs natively on asyncio without needing a separate ASGI server like uvicorn — a critical requirement for integration with the existing qasync event loop.

## Sync Compatibility

All new fields use the established backward-compatibility pattern:
- `to_dict()` includes new fields
- `from_dict()` uses `.get(field, default)` — older peers without the field get sensible defaults
- LWW merge replaces entire `TodoItem` objects — no field-level merge logic needed

## Verification Strategy

Each phase follows the same cycle:

1. `uv run ruff check --fix . && uv run ruff format .`
2. `uv run basedpyright`
3. `QT_QPA_PLATFORM=offscreen uv run python -m pytest tests/ -v`
4. Manual smoke test: `uv run python -m pytodo_qt`
