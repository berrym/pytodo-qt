## SQLite Schema Design

### Schema Version

```sql
-- Metadata table for schema versioning
CREATE TABLE metadata (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);

-- Initial metadata
INSERT INTO metadata (key, value) VALUES ('schema_version', '3');
INSERT INTO metadata (key, value) VALUES ('active_list_id', NULL);
```

### Lists Table

```sql
CREATE TABLE lists (
    id TEXT PRIMARY KEY,           -- UUID as string
    name TEXT NOT NULL,
    created_at INTEGER NOT NULL,   -- milliseconds since epoch
    updated_at INTEGER NOT NULL,
    deleted INTEGER NOT NULL DEFAULT 0  -- boolean as 0/1
);

CREATE INDEX idx_lists_deleted ON lists(deleted);
CREATE INDEX idx_lists_name ON lists(name);
```

### Items Table

```sql
CREATE TABLE items (
    id TEXT PRIMARY KEY,           -- UUID as string
    list_id TEXT NOT NULL,         -- Foreign key to lists
    reminder TEXT NOT NULL DEFAULT '',
    priority INTEGER NOT NULL DEFAULT 2,
    complete INTEGER NOT NULL DEFAULT 0,  -- boolean as 0/1
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL,
    deleted INTEGER NOT NULL DEFAULT 0,

    FOREIGN KEY (list_id) REFERENCES lists(id)
);

CREATE INDEX idx_items_list_id ON items(list_id);
CREATE INDEX idx_items_deleted ON items(deleted);
CREATE INDEX idx_items_complete ON items(complete);
CREATE INDEX idx_items_priority ON items(priority);
```

### Why This Schema

1. **UUIDs as TEXT**: SQLite doesn't have native UUID type. TEXT is standard practice.
2. **Booleans as INTEGER**: SQLite convention (0=false, 1=true).
3. **Millisecond timestamps**: Preserves current precision.
4. **Indexes**: Support efficient queries for common operations.
5. **Foreign key**: Maintains referential integrity.
6. **Metadata table**: Flexible key-value for schema version, settings.

def backup_json_file(json_path: Path) -> Path:
    """Create timestamped backup of JSON file.

    Returns:
        Path to backup file
    """
    timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
    backup_path = json_path.with_suffix(f".json.backup_{timestamp}")
    shutil.copy2(json_path, backup_path)

## Integration Points

### Changes to main_window.py

```python
# Before (current)
def _load_database(self) -> None:
    db_path = self._config_manager.db_file
    if db_path.exists():
        with open(db_path, encoding="utf-8") as f:
            data = json.load(f)
        self._database = Database.from_dict(data)

def _save_database(self) -> bool:
    with open(db_path, "w", encoding="utf-8") as f:
        json.dump(self._database.to_dict(), f, indent=2)

# After (new)
def __init__(self, ...):
    self._storage = DatabaseStorage(self._config_manager.db_file)
    self._storage.open()

def _load_database(self) -> None:
    # Check for JSON and migrate if needed
    json_path = self._config_manager.db_file.with_suffix('.json')
    if json_path.exists() and not self._config_manager.db_file.exists():
        migrate_json_to_sqlite(json_path, self._config_manager.db_file)

    self._database = self._storage.load_database()

def _save_database(self) -> bool:
    self._storage.save_database(self._database)

def closeEvent(self, event):
    self._storage.close()
    super().closeEvent(event)
```

## Migration Strategy

### Automatic Migration Flow

```
App starts
    │
    ▼
Check for SQLite database
    │
    ├─► Exists: Load from SQLite
    │
    └─► Not exists: Check for JSON
            │
            ├─► JSON exists:
            │       1. Backup JSON file
            │       2. Migrate to SQLite
            │       3. Load from SQLite
            │
            └─► No JSON: Create empty SQLite
```

### Migration Steps

1. **Backup**: Copy `pytodo-qt-db.json` to `pytodo-qt-db.json.backup_YYYYMMDD_HHMMSS`
2. **Load**: Parse JSON into `Database` object
3. **Create**: Initialize SQLite with schema
4. **Transfer**: Insert all lists and items
5. **Verify**: Compare counts (lists, items) match
6. **Complete**: Log success, app continues

### Rollback

If migration fails:
- SQLite file is deleted
- Original JSON remains untouched
- App falls back to JSON (one more release cycle)
- Error logged with details

### Edge Cases

| Scenario | Handling |
|----------|----------|
| Empty JSON database | Create empty SQLite, success |
| Corrupted JSON | Error, keep JSON, alert user |
| Disk full during migration | Rollback, keep JSON |
| Permission denied | Error, keep JSON |
| Legacy v0.2.x JSON | Migrate legacy → new JSON → SQLite |

2. **WAL mode**: Enable SQLite WAL mode for better concurrency?
   - **Recommendation**: Yes, enables concurrent reads during writes

3. **Connection pooling**: Single connection or pool?
   - **Recommendation**: Single connection is fine for desktop app

4. **Tombstone cleanup**: Should migration clean up old tombstones?
   - **Recommendation**: No, preserve for sync consistency. Add cleanup later (0.3.9 or 0.3.10)
