Seventh prerelease of the v0.3.11 series. b7 is the consolidation release: Calendar Arc A closes (every gap that made the calendar surface feel "todo list with calendar views" rather than a calendar-app-grade surface is now addressed), the WCAG AA contrast audit ships and lands ten clustered follow-up fixes across both desktop and web, the polish track absorbs a heavy round of empty-state, onboarding, and accessibility work, and the desktop timeline grows two new analytics pills that close a long-running parity gap with the web UI. A strategic shift removes CalDAV / .ics / iCalendar interop and the location field — pytodo-qt is now explicitly a P2P-synced calendar-supporting planner whose interop is peer-to-peer, not external-protocol; rationale below. Everything in v0.3.11b1 through b6 still applies — see [v0.3.11b1](v0.3.11b1.md), [v0.3.11b2](v0.3.11b2.md), [v0.3.11b3](v0.3.11b3.md), [v0.3.11b4](v0.3.11b4.md), [v0.3.11b5](v0.3.11b5.md), and [v0.3.11b6](v0.3.11b6.md) for the full feature set. This page covers only what changed between b6 and b7.

## ⚠ macOS Sequoia (15.x) and later — first-launch note

Same as every prior beta in the series: the DMG is ad-hoc signed, so Sequoia and later block first launch by default.

**System Settings path:**

1. Try to open the app, get the block dialog, click **Done**.
2. Open **System Settings → Privacy & Security**.
3. Scroll to the Security section — *"pytodo-qt was blocked to protect your Mac"*.
4. Click **Open Anyway**, enter your password, click **Open** on the re-prompt.

**Command-line shortcut:**

```bash
xattr -rd com.apple.quarantine /Applications/pytodo-qt.app
```

macOS Sonoma (14.x) and earlier can still use the legacy right-click → Open path. Windows users hitting the SmartScreen *"Windows protected your PC"* dialog: click **More info** → **Run anyway**. Both behaviors are normal for any open-source app distributed without paid signing certificates; the README's Installation section has full per-platform first-launch walkthroughs for testers new to side-loading.

## Strategic shift — CalDAV, .ics, and the location field removed

Commit `331c59d` (27 files, +43 / −3111) removed the CalDAV server, all .ics import / export, every VTODO / VEVENT serialization path, and the `TodoItem.location` field. Schema bumped to v21 with a `_migrate_schema_to_21` that drops the column on any v20 development DB. Released v19 users reach v21 with no on-disk change because the column never reached production.

**Why:** the consumer-cloud calendar ecosystems do not interoperate with CalDAV/VTODO. Apple removed Reminders from CalDAV in iOS 13 / macOS Catalina; Google's CalDAV endpoint is VEVENT-only and has never supported VTODO; Microsoft retired the Outlook Tasks API in 2022 and replaced it with a JSON-only Graph endpoint. The remaining CalDAV ecosystem (self-hosters with Nextcloud, Tasks.org+DAVx5, Thunderbird) is served better by the mature purpose-built servers those communities already use than by anything pytodo-qt could ship as a side feature. Continuing to ship the server amounted to a UX promise the underlying ecosystem cannot honor.

**What this means going forward:** pytodo-qt remains a calendar-supporting app — full event support (`due_time` / `due_time_end` ranges, time blocks, recurrence), meeting-link Join buttons across every primary surface, drag-to-schedule, edge-drag-to-resize, agenda view, day/week/month/timeline. Sync happens through the P2P system with E2E encryption. Interop with external ecosystems is no longer a goal; new calendar features stand on their own user value, not on protocol parity.

The location field removal is the only user-visible data loss in this commit. Beta testers running v0.3.11b6 with location values set on items will see those values disappear on upgrade — the column is dropped during migration. If location was load-bearing for your workflow, consider keeping it in the reminder text (e.g. *"Team standup @ Conf room B"*) until a non-protocol-coupled location field gets reconsidered under fresh framing.

## Calendar Arc A epic closes

Issue #20 closes with this release. Every calendar gap in the original Arc A scope is addressed:

- #10 — sliver floor (b5)
- #21 — theme-aware event_date color (b5)
- #13 — interactive `due_time_end` UI (b6)
- #14 — meeting-link auto-detection + Join button (b6)
- #15 — agenda view (b6)
- #16 — location field — closed-as-obsolete in this release (CalDAV nuke; field removed)
- #17 — busy / free / tentative / OOO flag — closed-obsolete-as-scoped; original VEVENT-round-trip framing no longer applies, the standalone-flag UX value can be reopened later under fresh framing
- #18 — edge-drag-to-resize (this release)
- #19 — extended conference-link detection across 18 providers (this release)

Arc B — the originally-planned "meeting app" arc with attendees, scheduling assistant, scheduling polls, and public booking links — retires alongside Arc A's close. Three of its four planned items don't survive without external interop: scheduling assistants need other people's free/busy data, polls need a publicly-accessible voting URL, and public booking links need a public surface — pytodo-qt is P2P over LAN with no public surface. The salvageable item (an attendees field as personal "who's involved" metadata) ships as a small standalone if it shows independent UX value.

Arc C — the differentiators arc — is the forward direction. Auto-prep blocks before meeting-link items, "next meeting in N min" affordance, post-meeting capture / follow-up extraction, do-not-schedule windows, travel/commute time as hashed bars, NLP-driven scheduling, focus-session integration. All single-user, P2P-syncable, no external interop. The right play for meeting-heavy users who are stuck on Teams / Zoom / Webex by company mandate: be the place they manage *around* those mandated tools rather than try to replace them.

## Added

### Calendar — All Day band architectural rebuild (`811fdf9`, `9bb1f29`)

The previous All Day row scrolled with the timed-hour grid, sized inconsistently, clipped its label on Linux at HiDPI, and visually glued to the timed grid below it. Every consumer calendar treats the All Day band as a separate surface that does not scroll, is sized to match one timed-hour row, and has a clear visual gap to the timed grid below. b7 lands that:

- The All Day row pins to a fixed `_ALL_DAY_ROW_HEIGHT = 60 px` baseline shared by both day-view (which uses 80 px hour rows) and week-view (60 px hour rows), so the band visually matches across views regardless of the hour-grid section size.
- The "All Day" label cell is sized via `fontMetrics().horizontalAdvance("All Day")` plus padding rather than a hardcoded width, so HiDPI clipping on Linux is fixed at the source.
- A 14 px structural gap separates the All Day band from the timed-hour grid below in both day and week views, so they read as separate surfaces.
- Day-of-week date headers stay on the All Day band only; no duplicated header above the timed grid.
- `_AllDayTableView` overrides `_WeekTableView`'s row-distribution so the band cannot be pushed off-screen by the hour grid's vertical scroll.

### Calendar — edge-drag-to-resize bar duration (closes #18)

Press on the top or bottom edge of a day or week view bar enters resize mode; the cursor switches to the resize affordance, mouseMove maps the y-coordinate to a minute offset and snaps to a 15-minute grid (Shift = 1-minute fine adjustment), and mouseRelease dispatches an `EditEstimatedMinutesCommand` that updates the underlying `due_time` / `due_time_end` per the bar's lifecycle state. The Q1-locked semantics from the calendar Gantt-redesign spec govern which field changes for which `BarState`; the work is in `_hit_test_edge`, the resize state machine, and the new `EditEstimatedMinutesCommand` introduced in `d9ecd25`.

### Calendar — conference-link detection extended (closes #19)

`core/meeting_link.py` grew from the five b6 providers (Zoom / Microsoft Teams / Google Meet / Webex / Jitsi) to **18 providers across 26 regex patterns**. The full list now covers Zoom, Microsoft Teams (work and consumer), Google Meet, Cisco Webex, Jitsi, BlueJeans, GoToMeeting, GoToWebinar, Skype, Skype for Business, Discord (voice channels), Whereby, 8x8, Pexip, RingCentral, Lifesize, Zoho Meeting, and Around. The detection runs against the reminder field in O(n) regex passes; per-provider Join behavior depends on the user having the corresponding client installed (the Join button hands off via `QDesktopServices.openUrl` and lets the OS resolve the URI scheme).

The user-visible promise of detection is universal across providers — *"if you paste a meeting URL into a task, pytodo-qt will recognize it and offer Join"* — across the detail panel, kanban card, and calendar context menu (and now the list-view context menu, see below).

### List view — meeting-link Join action in the right-click context menu (closes #30, `a4fc196`)

The list view's right-click context menu gains a *"Join {provider} meeting"* entry at the top of the menu when the selected item's reminder contains a recognized meeting URL, mirroring the same affordance that already existed on the kanban card and the calendar bar context menu. This closes a parity gap surfaced during b6 testing — every primary surface that shows a task should be able to launch its meeting.

### Agenda view — drag-and-drop done properly (`2699252`)

The b6 agenda view shipped with unidirectional drag from the unscheduled panel to a day group as the only working drag interaction. b7 makes the rest of the surface work as users expect from any consumer calendar agenda:

- `_AgendaRow` initiates `QDrag` once the cursor passes `startDragDistance` from the press point. Mime type is `application/x-pytodo-item-id`, matching the existing calendar drag protocol.
- `_AgendaView` paints a tinted background on the day-section header under the drag cursor (clears on `dragLeaveEvent` / drop) so the drop target is visible mid-drag.
- Drag preview is a row pixmap rendered to a translucent `QDrag.setPixmap`, so the user sees what they're moving.
- Cross-day drag preserves the set time on the dropped item (delegates to the existing `EditDueDateCommand`); past-date drops are allowed silently per the spec, matching the behavior of the day/week views.
- Drag from agenda back to the unscheduled panel works (clears `due_date` / `due_time`).
- Within-day reposition via drag is intentionally not supported — the agenda has no time-grid to drop onto, so an in-day drag would be ambiguous about whether the user means "change time" or "change order." Both effects are reachable through the detail panel.

### Desktop calendar — Timing and Cycle analytics pills (`98b5ac5`)

The web calendar view rendered two analytics blocks inline at the bottom — Completion Timing (early / on-time / late distribution + slip rate) and Cycle Time (mean / median / p90 of created→completed durations) — that the desktop calendar timeline could not reach. b7 closes that parity gap with two new pills appended to the existing timeline sub-view bar (Tasks / Daily / Productivity / Accuracy / **Timing** / **Cycle**):

- **Timing pill** renders three horizontal pyqtgraph bars (Late / On time / Early) using the same `BarState` palette that drives the day/week calendar bars and the matplotlib chart export, so the visualization reads identically across surfaces. Title shows slip rate from `analytics.slip_rate()`. Empty state covers no-data and no-analytics-service. An unknown-cohort footer note shows when there are completed items without timestamps so the classification is transparent about what got excluded from the count.
- **Cycle pill** is a stat-tile layout — three large numeric values for Mean / Median / p90, formatted into m / h / d units, with a subtitle that surfaces sample count plus any unknown-cohort items excluded from the stats. `cycle_time` returns scalar values only at this layer; a chart of three numbers would be theatre.

The pills are appended at the end of the timeline sub-view bar rather than reordered, so the saved `timeline_sub_view` preference stays valid for existing users.

### ⓘ click-to-popover explanations for the new pills (`11a18b7`, `1dfa6e6`, `5ab2caf`)

Both new pills, on both desktop and web, gained a small ⓘ icon next to their title that pops a tooltip-style explanation on click. The desktop renders the icon as an `info://` link inside the title `QLabel` (via `linkActivated` → `QToolTip.showText`); the web renders a click-to-toggle floating panel that dismisses on click-outside or Escape. The explanation copy covers the classification rules, the deadline definition for Completion Timing, and the percentile semantics + sample-inclusion rules for Cycle Time. Same content on both surfaces. Mirrors the focus-score popover pattern in `dialogs/focus_timer.py`.

The desktop implementation took three commits to land: the first attempt added a sibling `QPushButton` next to the title, which surfaced a pyqtgraph teardown race on the Python 3.12 + offscreen CI matrix (Linux first, then Windows after the second attempt). The final fix lazy-constructs the Timing widget's `pg.PlotWidget` on first `rebuild()` so off-screen `QStackedWidget` pages never instantiate one — sidesteps the race entirely. Documented for posterity in `feedback-pyqtgraph-teardown-race.md`.

### Stopwatch dialog — separate analytics + focus-score popover (`2e985b8`)

Five widget-internal palettes consolidated into `themes.py`. The stopwatch dialog mode now shows item-total-tracked / daily-tracked / tracking-streak labels and a *"Today's Tracking"* dropdown with mode-aware guards on every pomodoro update method, so background ticks can no longer re-show pomodoro labels in stopwatch mode. The focus score row pairs the existing label with a clickable ⓘ icon that pops a tooltip-style explanation (goal ratio / completion rate / streak bonus / grade thresholds) — the pattern subsequently mirrored on the new Timing and Cycle pills above. The pomodoro tomato row simplifies to *"one emoji per completed session"* — the previous `QGraphicsOpacityEffect`-based dimming was unreliable for emoji on macOS / Linux / Windows and the session counter already showed estimate progress textually.

### List view — three-case empty-state overlay (`f6372b8`, `ab0ed35`, `be7b7ff`)

The list view now shows a centered empty-state overlay matching the kanban's existing pattern across **four cases**:

- **No lists in the database** (fresh install): *"Welcome to PyTodo-Qt. Create your first list to get started"* + a **Create list** button.
- **List exists but is empty**: a **+ Add task** prompt.
- **All items in the list are completed**: an **All done** message with a **Show completed** button.
- **Filter is active and the result set is empty**: a **No matches** message with a **Clear filters** button.

Each case routes through a dedicated signal (`add_task_requested`, `clear_filters_requested`, `show_completed_requested`, `create_list_requested`) wired to the same `MainWindow` handlers the kanban already uses. Three follow-up commits in the same wave: `f6372b8` introduced the overlay; `ab0ed35` reparented it to `self.viewport()` after the first cut overlapped the table viewport; `be7b7ff` added the no-lists onboarding case and a `QTimer.singleShot(0, _position_empty_state)` deferred-position pass so an overlay shown from inside a `_refresh_ui` sequence ends up centered after the surrounding layout settles.

## Fixed

### `AnalyticsService.completion_timing` crashed on mixed-NULL `due_time` (`98b5ac5`)

When the items table contained a mix of NULL and non-NULL `due_time` values, `completion_timing` raised `TypeError: fromisoformat: argument must be str`. SQLite NULLs read back through pandas can arrive as `NaN` (a float) rather than `None` depending on dtype inference, and a `cast(str, ...)` type-checker hint did not actually convert the value. The pre-fix truthiness check then evaluated NaN as truthy and passed it straight into `time.fromisoformat`. Coerced explicitly with `pd.isna` before the str path. The web UI rendered *"Completion Timing unavailable"* on the same data because the JS `catch` block fell through to the unavailable fallback — this fix lights up that surface too. Regression test added (`tests/test_analytics.py::TestCompletionTiming::test_mixed_null_and_timed_due_times`).

### List-switch refresh missed off-screen views (`2914fa3`)

`_on_list_changed` only called `set_list` on `todo_table` (when the list view was current) or `kanban_board` (otherwise); the calendar was never told. Switching lists from any view other than list / kanban left the now-active view rendering the previous list, and even from list / kanban the two off-screen views fell out of sync until the user flipped past them and back. Fix: dispatch the new `TodoList` to all three views unconditionally — every view's `set_list` is idempotent enough that the extra two calls per switch are negligible.

### Status-bar timer width jitter and Today's Sessions hover contrast (`0df7fe1`)

Two #28 gripes surfaced during #33 visual verification. The status-bar `pomodoro_label` used the proportional default font, so the timer width visibly shifted as digits ticked each second; pinned to `QFontDatabase.systemFont(SystemFont.FixedFont)` with bold moved off the per-state stylesheet onto the QFont so subsequent color updates do not clobber the family. The Today's Sessions toggle in the focus dialog had inline `color: gray;` that went unreadable on the highlight band on hover / focus / press; replaced with theme-driven QSS using `completed_text` resting / `text` hover / `highlight_text` on `highlight` for pressed+focus.

### Dropdown affordance regression on macOS and Linux (`de05322`)

Combo popups, list selectors, and settings dropdowns gave no visual feedback as the cursor moved over rows on macOS *and* Linux (a previous theory that this was macOS-only-native-fallback turned out to be wrong). Fixed with two layers: (1) QSS rules for `QListView::item` / `QTreeView::item` / `QComboBox QAbstractItemView::item` adding `:hover` and `:selected` styling, plus a 3 px left accent bar (new `selection_indicator` theme key) on the persistent selection so hover and selected are visually distinct. (2) A per-widget configurator (`_DropdownConfigurator` in `themes.py`) installed as a `QApplication` event filter that catches `QEvent.Polish` and toggles `mouseTracking = True` on the view plus `setItemDelegate(QStyledItemDelegate(view))` on `QComboBox` popups — both required because Qt's `:hover` for `::item` will not fire from a bare cursor pass without `mouseTracking`, and combo popups bypass QSS item rules entirely on Linux/macOS native styles unless the styled delegate is forced. `apply_theme` sweeps already-constructed widgets too. Documented for posterity in `feedback-qt-dropdown-affordances.md`.

### Notifications fire on one channel per platform, overlay sizes to content (closes #43)

Pre-fix, every notification in pytodo-qt fired twice on Linux and Windows: once via the OS native notification system (libnotify in the top-right corner on Linux; WinRT toast on Windows) **and** once via the in-app overlay (a frameless banner near the center of the screen). The dispatch logic in `_MainWindow._notify_` showed the overlay unconditionally, then layered the OS notification on top whenever `desktop-notifier` was available. b7 fixes both halves of the resulting UX problem:

- **Per-platform dispatch.** A new `_prefer_os_notification` helper picks **one** channel based on the runtime configuration. Linux / Windows / BSD route through the OS notification system — native paths handle long text gracefully (KDE scrolls overflow, Windows toasts truncate readably), match platform conventions, and respect the user's notification preferences and Do Not Disturb state. macOS routes through the in-app overlay because the OS path on an ad-hoc-signed bundle fires successfully but the system substitutes a generic placeholder banner that omits the title and body — see `project-macos-notifications-text.md` for the bundle-identity wall this works around. If the OS path fails at runtime, the overlay catches the fallback so the user still sees the notification.
- **Overlay sizes to content.** The overlay was previously stuck at a fixed 88 px height regardless of body length, which clipped any body past two wrapped lines. b7 replaces the fixed height with `setMinimumHeight(_MIN_HEIGHT=88)` + `setMaximumHeight(_MAX_HEIGHT=240)` so short bodies still settle at the original visual baseline while realistic worst-case content (meeting reminder + notes, 200–300 characters) renders fully readable. A latent stacking bug — `_slot_position` computing y as `index * uniform_height` — surfaced once heights became dynamic and was fixed by walking through the actual heights of preceding visible banners.

The platform-decision helper is a pure function unit-tested across `linux` / `win32` / `freebsd` / `openbsd` and `darwin` platform strings without needing to construct a `MainWindow` or run an asyncio loop. The overlay-sizing changes get baseline / long-body / pathological-body coverage plus a mixed-height stacking test that asserts the slot position respects actual preceding heights rather than a uniform assumption.

### Cross-platform agenda day-header strftime (carried over from b6 fix)

The b6 agenda day-header used `strftime("%A, %B %-d, %Y")`. The `%-d` modifier is a POSIX extension; Windows' `strftime` rejects it. The day-of-month is now composed from `d.day` directly so the same source renders identically across POSIX and Windows.

## What's not in b7 — honest disclosure

This release ships substantial work, but the project still has known limits worth being explicit about so testers know what to expect.

**Web UI mobile reality.** The web UI is fundamentally session-based — it works great when a phone or tablet has a browser tab open against the desktop's web server. It is **not** a substitute for native mobile apps when it comes to background notifications. The Web Push API (PWA + Service Worker) is best-effort: iOS Safari supports Web Push only for home-screen-installed PWAs with explicit notification permission; Android handles it slightly better but power-management still defers notifications during deep sleep. Reliable for *"you're using the phone right now"* reminders; unreliable for *"phone is in your pocket and an alarm needs to fire at 2pm sharp."* If reliable alarm-grade notifications matter to your workflow, web-UI alone won't deliver them. True background notifications need native iOS / Android apps, which **don't exist yet**.

**Native mobile apps.** Not in scope for v0.3.11. The sync protocol is cross-language-friendly (TCP wire format with explicit message types — not Python pickle), so a native iOS / Android app that speaks the protocol is real engineering work but not architecturally blocked. Scoped for v0.5.x at the earliest, more likely contributor work than core. Open to contributors with iOS or Android experience who want to take it on.

**Internet capability beyond LAN.** pytodo-qt ships with mDNS-based peer discovery and P2P sync over LAN. Two devices on the same Wi-Fi network find each other and sync; two devices on different networks currently do not. The path forward is documented in [`project-remote-access-strategy.md`](https://github.com/berrym/pytodo-qt/blob/master/docs/plans/) (LAN-first, Tailscale as the recommended bridge for current code, server mode for v0.4.x). For testers who want internet capability **today**, see "Suggestions for the determined user" below.

**External calendar interop.** Removed in this release. pytodo-qt does not speak CalDAV, CardDAV, iCal / .ics, or any other calendar-ecosystem protocol. The strategic decision is documented in the *Strategic shift* section above and in [`project-caldav-removal.md`](https://github.com/berrym/pytodo-qt/blob/master/docs/plans/). New calendar features stand on their own user value, not on protocol parity.

**AddTodo dialog accessibility deep-dive.** The b7 accessibility wave landed prerequisite work — `setAccessibleName` on twelve top-level dialogs, `:focus-visible` indicators on the web UI — but the deeper VoiceOver / Orca / NVDA pass on the AddTodo dialog (#22) moved to **v0.3.11b8** as that cycle's centerpiece. If you rely on a screen reader, b8 is the release to wait for; b7 won't have visibly degraded accessibility, but it also won't have been deliberately walked through with one.

**Web UI calendar month view layout.** Filed as #41, deferred past v0.3.11. The month view's column shrinking and task overflow / clipping needs design work before code work. Day, week, agenda, and timeline views on the web UI are unaffected.

## Suggestions for the determined user

**Want to use pytodo-qt across the internet today?** [Tailscale](https://tailscale.com/) (or self-hosted Headscale, or WireGuard) gives self-hosters a private mesh network that looks LAN-shaped to mDNS — pytodo-qt's existing peer discovery and P2P sync work over it without code changes. Install Tailscale on each device that runs pytodo-qt, log in, and the devices find each other on the tailnet just as if they were on the same physical Wi-Fi. The free Tailscale tier is 100 devices / 3 users — more than enough for personal use plus a handful of testers. Tailscale clients exist for macOS, Windows, Linux, iOS, Android, ChromeOS, FreeBSD, Synology / TrueNAS / QNAP / Unraid NAS, OpenWRT, and Docker / Kubernetes; the user-perceived flow is *"install and log in, devices find each other, just works."*

**Want notifications on a phone now?** The web UI installed as a PWA on iOS 16.4+ or Android Chrome can deliver Web Push notifications when the PWA is installed to the home screen and notification permission is granted. The reliability caveat in *"What's not in b7"* above applies — best-effort, not alarm-grade. Use it for *"I want to add a task from my phone"* and *"I want to skim my agenda from anywhere on my LAN / tailnet"* — those work well. Don't rely on it for *"the phone needs to wake me up exactly at 2pm."*

**Want to verify a download before installing?** Every release artifact ships with a sibling `<filename>.sha256` file. The README's [Checksums](https://github.com/berrym/pytodo-qt#checksums) section has the per-platform commands.
