Second prerelease of the v0.3.11 series. Ships fixes for two user-visible rendering bugs and a complete rewrite of the macOS system-notification path. Everything in v0.3.11b1's notes still applies — see [v0.3.11b1](v0.3.11b1.md) for the full feature set (installers, calendar, smart-add, kanban, NLP, settings, mobile access). This page covers only what changed between b1 and b2.

## ⚠ macOS Sequoia (15.x) and later — first-launch note

Same as b1: the DMG is ad-hoc signed, so Sequoia and later block first launch by default.

**System Settings path:**

1. Try to open the app, get the block dialog, click **Done**.
2. Open **System Settings → Privacy & Security**.
3. Scroll to the Security section — you'll see *"pytodo-qt was blocked to protect your Mac"*.
4. Click **Open Anyway**, enter your password, click **Open** on the re-prompt.

**Command-line shortcut:**

```bash
xattr -rd com.apple.quarantine /Applications/pytodo-qt.app
```

macOS Sonoma (14.x) and earlier can still use the legacy right-click → Open path.

## Fixed

### System notifications (macOS)

- Migrated from Qt's `QSystemTrayIcon.showMessage` to [`desktop-notifier`](https://github.com/samschott/desktop-notifier) (MIT). On macOS, Qt's implementation never called `UNUserNotificationCenter.requestAuthorization`, which caused the DMG-installed app to render anonymous **"PyTodo-Qt Notification"** banners with empty bodies. `desktop-notifier` issues the authorization request properly, so notifications now show full title + body. First launch of b2 will trigger a one-time macOS permission prompt.
- Linux (libnotify) and Windows (WinRT) notification paths are updated through the same API. Linux behavior is unchanged in practice; Windows gets the same title + body fidelity it previously lacked.
- Graceful degradation when the process runs outside a proper app bundle (e.g. `uv run` from source on macOS): notifications silently log at DEBUG and don't crash.

### Calendar week view — recurring and future-dated task rendering

- Daily-recurring tasks no longer flip the rest of the week to green (completed) after you finish today's occurrence. `_ProjectedItem` proxies for future dates were inheriting the template's `complete` / `completed_at` state; they now override both so a projection is always treated as a future occurrence that hasn't happened yet.
- Non-recurring tasks dated in the future no longer render as overdue (red) when viewed from an earlier day. The `_as_of_for_viewing_day` reference moment for future viewing days was end-of-day, which asked "will it be overdue by midnight?" for any incomplete task with a due_time; it now clamps to `current_time`. Past-day historical semantics unchanged.
- Both fixes are coupled: either fix alone leaves the visual broken in a different color (green ↔ red). They shipped together in one commit (`a512084`).

### Calendar auto-advance

- Recurring-task anchor now advances correctly when the wall-clock day crosses while the app is open.

## Internal

- **basedpyright hygiene:** 164 errors and 111 warnings cleared across `src/`. Typecheck now reports 0 errors on master.
- **PyInstaller spec:** `desktop_notifier` submodules and `rubicon.objc` added to `hiddenimports` so the macOS DMG bundles the new notification backend correctly.
- **Docs:** macOS Sequoia+ Gatekeeper first-launch guidance added to `README.md`.

## Known limitations

- Downloading the DMG via `gh run download` or any other mechanism that strips the `com.apple.quarantine` xattr will suppress the first-launch permission prompt. Download from the browser on the release page instead, so Gatekeeper sees the quarantine flag and macOS triggers the permission flow.
- First-party release tags are still unsigned (ad-hoc only). Developer ID signing + notarization is a v0.4.x goal.
