# v0.3.11b8

Eighth prerelease of the v0.3.11 series. b8 is the accessibility-and-polish release: the AddTodo dialog's programmatic accessibility audit ships and every gap it found is fixed, the broken font selector is repaired and the default font behavior is corrected, the calendar gains a universal hover "+" add-task affordance with motion polish, the focus-session timer gets an attention cue so a new user can't miss that it is live and clickable, and a class of pytest-only teardown instability is eliminated so the build matrix is reliably green. There is one user-visible behavior change: the application font now defaults to the platform system font rather than bundled Noto Sans (existing configs are preserved; rationale below). Everything in v0.3.11b1 through b7 still applies — see [v0.3.11b1](v0.3.11b1.md), [v0.3.11b2](v0.3.11b2.md), [v0.3.11b3](v0.3.11b3.md), [v0.3.11b4](v0.3.11b4.md), [v0.3.11b5](v0.3.11b5.md), [v0.3.11b6](v0.3.11b6.md), and [v0.3.11b7](v0.3.11b7.md) for the full feature set. This page covers only what changed between b7 and b8.

## ⚠ macOS Sequoia (15.x) and later — first-launch note

Same as every prior beta in the series: the DMG is ad-hoc signed, so Sequoia and later block first launch by default.

**System Settings path:**

1. Try to open the app, get the block dialog, click **Done**.
2. Open **System Settings → Privacy & Security**.
3. Scroll to the Security section — *"pytodo-qt was blocked to protect your Mac"*.
4. Click **Open Anyway**, enter your password, click **Open** on the re-prompt.

**Command-line shortcut:**

```bash
xattr -rd com.apple.quarantine /Applications/pytodo-qt.app
```

macOS Sonoma (14.x) and earlier can still use the legacy right-click → Open path. Windows users hitting the SmartScreen *"Windows protected your PC"* dialog: click **More info** → **Run anyway**. Both behaviors are normal for any open-source app distributed without paid signing certificates; the README's Installation section has full per-platform first-launch walkthroughs.

## Accessibility — AddTodo dialog audit and fixes

The programmatic half of the AddTodo accessibility audit (#22) ships as `scripts/audit_add_todo_a11y.py`, which walks every focusable widget in the dialog and reports gaps across seven classes. The first run found 44 gaps across 36 widgets; six per-class follow-up issues were filed and all six landed:

- **#47** — the Advanced disclosure was not keyboard-reachable, which blocked every Advanced field from keyboard-only users. It now takes focus and toggles via keyboard.
- **#48 / #49** — form-row labels (12) and group-box titles (4) gained Alt+letter mnemonics. Letters were chosen for uniqueness and to avoid colliding with the dialog's Ok / Cancel.
- **#50** — the four quick-action buttons announced their decorative drop-arrow glyph to screen readers; they now carry an explicit accessible name with the bare label.
- **#51** — twelve Advanced fields and the smart input gained explicit accessible names.
- **#52** — paired controls that shared one form-row label (the Repeat row, the Ends row, the duration value+unit pair, the recurrence interval+type pair) gained distinct accessible names and descriptions so each control announces unambiguously.

After the cluster, the audit reports **zero gaps across all seven classes**. The audit script is committed and re-runnable, so regressions surface immediately.

#22 stays open as the audit umbrella until the manual screen-reader walkthrough (VoiceOver / Orca / NVDA) and tab-only passes are recorded. **That walkthrough is exactly what this prerelease is for** — if you use a screen reader, b8 is the build to exercise the AddTodo create-a-task flow against, and to file notes on.

## Added

### Calendar — universal hover "+" add-task button (`e1eea87`, `c085541`, closes #57)

Hovering any hour-grid cell in the day or week calendar now shows a floating "+" button that adds a task at that cell's date and hour, whether the cell is empty or already holds task bars. It is a custom-painted circle (perfect on every platform regardless of native button styling) with a drop shadow, a 200 ms fade-in / 150 ms fade-out, an OutCubic slide when the cursor moves between cells, and it hides on scroll so its position never goes stale. Clicking the circle opens the add flow pre-filled with that date and hour; clicks in the transparent shadow halo fall through to the calendar.

### Status bar — focus-session attention halo (`eb12e75`)

When a pomodoro or stopwatch session starts, a soft halo around the bottom-of-window timer pulses three times then settles to a faint steady ring for the rest of the session, fading out when the session ends. A new user could previously miss that the timer is live and clickable; the pulse draws the eye, the steady ring is a quiet "active here" cue. The halo color tracks the session type — a paused stopwatch keeps its blue rather than flipping to the shared paused amber. It is mouse-transparent, so clicking the timer still opens the focus dialog.

## Improved

### Detail panel — window grows and shrinks with the panel (closes #55)

Showing the detail panel grows the window to make room for it; hiding the panel shrinks the window back to its no-panel width instead of leaving a blank gap. The toolbar toggle, the keyboard shortcut, the dock close button, and programmatic shows all route through one handler so the behavior is consistent regardless of how the panel is opened or closed.

### Notification overlay — long bodies scroll instead of clipping (`2e8d9bd`, `5c159cf`)

The in-app notification overlay (the fallback banner for macOS users without a paid Apple Developer ID, and the consistent banner everywhere else) now grows to fit its content up to a maximum height, then scrolls the body past that cap instead of clipping or compressing text. The first word of the first line is always visible on arrival. A visual-verification harness (`scripts/verify_notification_overlay.py`) backs the change and exposed a separate dismissal race that stranded mixed-height banners when several were dismissed at once — fixed in the same work.

### Tooltips — square corners across every surface (closes #54, `d48b664`, `ca8a555`)

Persistent calendar tooltips and tool-window labels now use square corners consistently, matching the rest of the app's tooltip styling rather than mixing rounded and square depending on the surface.

## Fixed

### Font selector did nothing; default font corrected (closes #42)

The Settings → Appearance font selector was effectively a no-op: changing it wrote the config to disk but never re-applied the font, so nothing changed until the next launch — and even then the "System default" choice silently fell back to whatever font was last applied. Both bugs are fixed: a single apply path is shared by startup and the Settings dialog, the selector applies live (a hint notes that the timer digits and table rows refresh on next restart), and the system-font branch now resolves the actual platform UI font.

The default font setting changes from bundled Noto Sans to the platform system font (San Francisco on macOS, Segoe UI on Windows, the desktop default on Linux), which matches the documented design intent. **Existing installs are unaffected** — a config that already says `font = "bundled"` keeps Noto Sans; only fresh installs get the new default. Bundled Noto Sans remains selectable, and the bundled emoji fallback (which keeps pomodoro and other emoji rendering on Linux) is independent of this setting and unchanged.

### Recurring tasks no longer project past their end count (closes #53)

A recurring task with a finite "ends after N occurrences" rule was projected onto calendar cells indefinitely, past the configured end count. Projection now stops at the Nth occurrence.

### Build stability — pytest-only pyqtgraph teardown race eliminated (`e097470`, `6b15bcc`, `7404296`, `be0a174`)

A class of intermittent CI failures — `RuntimeError: wrapped C/C++ object of type ViewBox has been deleted`, raised inside pyqtgraph during widget teardown under pytest-qt's rapid construct/destruct cycle — is eliminated. The remaining eagerly-constructed pyqtgraph chart widgets were made lazy (constructed on first show, not in `__init__`), a test-only event-flush fixture drains deferred events before teardown, and a test-only guard wraps the offending pyqtgraph internal so a deleted ViewBox can no longer escalate into a failure. **This is test-infrastructure hardening; the production binary is unaffected** — none of the test-only pieces ship in release artifacts. The practical effect for testers is simply that the build matrix is reliably green.

## What's not in b8 — honest disclosure

**AddTodo manual screen-reader walkthrough.** The programmatic audit is complete and reports zero gaps, but the deliberate VoiceOver / Orca / NVDA pass through the create-a-task flow is owner / tester manual work that is done *against this prerelease*, not before it. b8 will not have visibly degraded accessibility, but the manual walkthrough notes are still to be recorded. Screen-reader users testing b8 and filing notes is the single most valuable feedback this release can receive.

**Web UI calendar month view layout.** Still filed as #41, still deferred past v0.3.11. Column shrinking and task overflow / clipping in the month view need design work before code work. Day, week, agenda, and timeline views on the web UI are unaffected.

**Native mobile apps.** Not in scope for v0.3.11. The sync protocol is cross-language-friendly, so a native iOS / Android client is real engineering work but not architecturally blocked; scoped for v0.5.x at the earliest, more likely contributor work than core.

**Internet capability beyond LAN.** pytodo-qt ships with mDNS-based peer discovery and P2P sync over LAN. Cross-network sync is not built in; the recommended bridge for current code is a private mesh (see below). External calendar interop (CalDAV / .ics / iCal) remains removed as of b7 — pytodo-qt is a P2P-synced planner whose interop is peer-to-peer, not external-protocol.

## Suggestions for the determined user

**Want to use pytodo-qt across the internet today?** [Tailscale](https://tailscale.com/) (or self-hosted Headscale, or WireGuard) gives a private mesh that looks LAN-shaped to pytodo-qt's mDNS discovery — existing peer discovery and P2P sync work over it with no code changes. Install on each device, log in, and the devices find each other on the tailnet as if on the same Wi-Fi.

**Want to verify a download before installing?** Every release artifact ships with a sibling `<filename>.sha256` file. The README's [Checksums](https://github.com/berrym/pytodo-qt#checksums) section has the per-platform commands.

**Want to help test?** The README's [Helping test the beta](https://github.com/berrym/pytodo-qt#helping-test-the-beta) section has a focused flow that exercises the most material parts of the app in about 15 minutes. For b8 specifically, the AddTodo dialog keyboard-only and screen-reader passes are the highest-value feedback. Issues at https://github.com/berrym/pytodo-qt/issues; being non-technical is welcome.
