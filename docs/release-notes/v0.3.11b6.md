Sixth prerelease of the v0.3.11 series. b6 is the calendar-app-vibes release: an interactive end-time field replaces the previous read-only display, video-conference URLs in task text now produce a Join button across every reachable surface, and a fifth chronological agenda sub-view sits alongside Day / Week / Month / Timeline so "what's coming up next, in order" reads as a single scrollable list. The README also gets a beta-visibility callout so the GitHub front page surfaces the v0.3.11 capability delta over v0.3.10. Everything in v0.3.11b1 through b5 still applies — see [v0.3.11b1](v0.3.11b1.md), [v0.3.11b2](v0.3.11b2.md), [v0.3.11b3](v0.3.11b3.md), [v0.3.11b4](v0.3.11b4.md), and [v0.3.11b5](v0.3.11b5.md) for the full feature set. This page covers only what changed between b5 and b6.

## ⚠ macOS Sequoia (15.x) and later — first-launch note

Same as every prior beta in the series: the DMG is ad-hoc signed, so Sequoia and later block first launch by default.

**System Settings path:**

1. Try to open the app, get the block dialog, click **Done**.
2. Open **System Settings → Privacy & Security**.
3. Scroll to the Security section — *"pytodo-qt was blocked to protect your Mac"*.
4. Click **Open Anyway**, enter your password, click **Open** on the re-prompt.

**Command-line shortcut:**

```bash
xattr -rd com.apple.quarantine /Applications/pytodo-qt.app
```

macOS Sonoma (14.x) and earlier can still use the legacy right-click → Open path.

## Added

### Interactive `due_time_end` UI in detail panel and AddTodo dialog (closes #13)

The parser has populated `due_time_end` since the b3 series via NLP patterns like *"from X to Y"* and *"between X and Y"*, and the bar-window EVENT rule has rendered windows correctly when the field is set. The UI to *edit* the field after creation existed nowhere — the detail panel showed nothing for it, and AddTodo's Advanced disclosure had no equivalent of the existing Due Time row.

- **AddTodo Advanced disclosure** now exposes an **End Time** row directly under Due Time, paired with a checkbox so the field can be unset. The checkbox is gated on Due Time being set: a window with no start has no meaning, and clearing Due Time cascades to End Time. The smart-input sync populates the row from `result.due_time_end` so opening Advanced after typing a range phrase shows the parsed end time as editable; the advanced-mode submit reads the field and constructs the `TodoItem` with the end time set.
- **Detail panel** grows an **End time** `QTimeEdit` under the existing Due time row, mirroring the same edit-mode-gated pattern. A new `item_due_time_end_changed` signal emits on edit-mode changes; MainWindow routes it through a new `EditDueTimeEndCommand` that mirrors `EditDueTimeCommand`, so the change participates in the existing undo stack and triggers the standard save / refresh cascade.

### Meeting-link auto-detection and Join button (closes #14)

A meeting URL pasted into a task's reminder is the most common signal that a task represents a real meeting, but until now there was no in-app affordance to launch the meeting from any view — copy-paste into a browser was the only path. The new `core/meeting_link` module provides a pure-Python regex detector for the five most-common providers:

- **Zoom** (`*.zoom.us/j/`, `*.zoom.us/my/`, etc.)
- **Microsoft Teams** (both `teams.microsoft.com/l/meetup-join/` and `teams.live.com/meet/`)
- **Google Meet** (`meet.google.com/`)
- **Cisco Webex** (`*.webex.com/meet/`, `wbxmjs/`, `j.php/`, `w.php/`, `webappng/`)
- **Jitsi** (`meet.jit.si/`)

Detection runs against the reminder field (notes / comments fields are out of scope — that work tracks separately under the rich-annotation roadmap). Three surfaces consume the detector:

- **Detail panel** shows a prominent Join button below the title row, labeled with the provider name (*"Join Zoom meeting"*). Click opens the URL via `QDesktopServices.openUrl`.
- **Kanban card** shows a compact Join button below the title row, conditional on detection.
- **Calendar bar context menu** gains a *"Join {provider} meeting"* entry at the top of the right-click menu when a meeting URL is present, followed by a separator before the existing Edit / Tags / Recurrence actions.

Long-tail conference providers (BlueJeans, GoToMeeting, Skype, Discord, Whereby, etc.) are tracked separately and queued for v0.3.11b7 (#19).

### Schedule / agenda sub-view (closes #15)

The calendar widget previously offered Day, Week, Month, and Timeline sub-views — three spatial layouts plus a statistics surface. None served the *"what's coming up next, in order"* mental model that consumer calendars (Google, Apple Calendar iOS, Outlook, Fantastical) all expose as a Schedule or Agenda view: a single scrollable chronological list, grouped by day with day-header rows, that lets a user scan upcoming items linearly without navigating between weeks and months.

- New **Agenda** pill in the calendar's sub-view button row, alongside Day / Week / Month / Timeline.
- Each day section has a header row (today's header is highlighted so it remains anchored when scrolling far ahead) followed by one row per scheduled item.
- Each row shows time-or-*"All Day"*, priority dot, reminder text (line-through and muted on completed items), and compact tag chips capped at 3 with overflow count. Click forwards to the detail panel via the existing `item_selected` signal.
- All-day items render before timed items within a single day; timed items sort chronologically.
- Days with no scheduled items show a muted *"(no scheduled items)"* placeholder so absence is visible.
- Navigation prev / next shifts the anchor by 30 days; today resets to today.

## Fixed

### Cross-platform agenda day-header formatting

The first cut of the agenda day-header used `strftime("%A, %B %-d, %Y")` to render *"Friday, May 1, 2026"* without a leading zero on the day-of-month. The `%-d` modifier is a POSIX extension; Windows' strftime rejects it with `ValueError("Invalid format string")`, which would have cascaded through the entire calendar test surface on Windows. The day-of-month is now composed from `d.day` directly, so the same source renders identically across POSIX and Windows.
