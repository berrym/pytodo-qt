Fourth prerelease of the v0.3.11 series. Critical packaging fix: the b1, b2, and b3 binary artifacts (DMG, Linux tarball, AppImage, Windows installer) all shipped without the runtime data files that the NLP smart input and the web UI need to function. b4 restores those files to the bundle and adds three layered build-time smoke tests so the regression class cannot recur silently. Everything in v0.3.11b1 through b3 still applies — see [v0.3.11b1](v0.3.11b1.md), [v0.3.11b2](v0.3.11b2.md), and [v0.3.11b3](v0.3.11b3.md) for the full feature set. This page covers only what changed between b3 and b4.

## ⚠ macOS Sequoia (15.x) and later — first-launch note

Same as b1 through b3: the DMG is ad-hoc signed, so Sequoia and later block first launch by default.

**System Settings path:**

1. Try to open the app, get the block dialog, click **Done**.
2. Open **System Settings → Privacy & Security**.
3. Scroll to the Security section — *"pytodo-qt was blocked to protect your Mac"*.
4. Click **Open Anyway**, enter your password, click **Open** on the re-prompt.

**Command-line shortcut:**

```bash
xattr -rd com.apple.quarantine /Applications/pytodo-qt.app
```

macOS Sonoma (14.x) and earlier can still use the legacy right-click → Open path.

## Fixed

### Bundled binaries no longer ship without runtime data

`packaging/pyinstaller/pytodo-qt.spec` previously collected only `gui/icons/`, `gui/fonts/`, `gui/sounds/`, and `qt.conf` into the build's `datas` list. Two later-added subsystems were never added to that list: the NLP intent dictionaries that `core/nlp_parser` loads via `importlib.resources.files(__package__)` from `core/intents/*.yaml`, and the web UI assets that `web/server.py` serves via aiohttp's static handler from `web/static/`. The b1, b2, and b3 binaries on every platform shipped without either tree, with two visible consequences:

- **AddTodo dialog rejected every submission.** With the intent dictionaries absent, `parse()` raised on first call inside the smart input's debounce-fired Qt slot. The exception was swallowed by Qt's slot machinery; `self._parse_result` stayed at the initial empty `ParseResult(reminder="")`. Every Enter or OK saw an empty reminder and produced *"Please enter a reminder"* regardless of what was typed. The Advanced disclosure's reminder field still worked, since it bypassed the parser entirely. NLP entity chips never rendered for the same reason — `_update_chips()` ran below the failing line.
- **Web UI served only a faded title.** With `web/static/` absent, the aiohttp server's `_serve_index` fell through its (now-removed) stub fallback, returning *"PyTodo-Qt Web UI"* as plain HTML. Every `<script src=...>` 404'd. The PWA shell loaded; the SPA never mounted. Mobile pairing reached the page but produced no usable interface.

Source-mode runs (`uv run pytodo-qt`) were unaffected because the source tree itself contains both directories — only the *frozen build* was missing them.

`collect_data_files` (already imported, previously unused) now walks `pytodo_qt.core.intents` and `pytodo_qt.web/static` and collects every non-Python file. Future additions to either subdirectory are bundled automatically with no spec change.

## Added

### Layered build-time verification

Three independent smoke tests run on every platform job after the PyInstaller build and before macOS signing, so a defective bundle never reaches a signed artifact or the release page:

- **Bundle filesystem verifier (`packaging/pyinstaller/verify_bundle_assets.py`).** Derives the expected file set from `git ls-files src/pytodo_qt/`, then asserts each non-Python tracked file appears at the corresponding relative path inside the bundled `pytodo_qt/` directory. The expected set updates automatically as new data files are tracked; build-only assets that PyInstaller relocates via EXE/BUNDLE icon parameters (`.icns`, `.ico`) are explicitly excluded. Catches the regression class fixed above directly.
- **Frozen-binary launch smoke.** Each build job runs the freshly-built executable with `--version`. argparse exits 0 once the binary boots Python far enough to print its version, so a non-zero exit catches broken imports, missing C extensions, dyld errors, and signature problems independently of the data-bundling check.
- **Runtime loader self-test.** `__main__` now accepts a hidden `--self-test` flag that runs before any Qt initialization, calling `core.intents.get_intents()` and `web.server._verify_static_assets()` in turn. Each succeeds silently or raises a `RuntimeError` with an actionable message; the handler prints the result and exits 0 or 1. Catches loader-path regressions that file presence alone would not, for example if `importlib.resources` semantics ever drift relative to `Path(__file__)` under freeze.

The three tiers cover the bundle from filesystem, runtime-import, and loader-path angles. Each tier independently catches a distinct class of regression; none duplicates another's coverage.

## Changed

### Loud failures replace silent degradation

- **`core/intents/load_intents`** wraps `FileNotFoundError` from `importlib.resources` into a `RuntimeError` whose message names the missing language file and the bundling constraint. Previously the bare `FileNotFoundError` was opaque under frozen builds.
- **`__main__`** preflights the intent dictionary at startup (between `QApplication` creation and the instance lock). On failure, a `QMessageBox.critical` shows the actionable error and the process exits, so a missing dictionary surfaces visibly instead of being lost inside a Qt slot exception.
- **`web/server.create_app`** now runs `_verify_static_assets` at the top, raising a `RuntimeError` that names missing files when the static directory or its required entries (`index.html`, `sw.js`) are absent. The previous silent fallbacks — conditional `add_static`, stub HTML response from `_serve_index`, 404 from `_serve_sw` — are removed: with upfront validation those file-existence checks were unreachable, and the rule against defending scenarios that cannot happen makes them dead code.

## Notes

The smart input parser still exhibits filler-word leakage in long natural-speech inputs (e.g. *"buy groceries tomorrow at 11am @errands it's a high priority"* yields a reminder of *"buy groceries it's a"* — entities extract correctly but connective tissue between extracted spans survives in the reminder). This is a separate source-level refinement gap, tracked independently and scheduled for a later beta. Current b4 fixes the binary regression that prevented any natural-speech input from being processed at all.
