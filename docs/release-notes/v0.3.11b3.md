Third prerelease of the v0.3.11 series. Continues the work shipped in b2 with substantial calendar polish, an in-app notification banner that complements system notifications, the first complete subtask CRUD surface in the detail panel, bidirectional drag-and-drop between calendar cells and the unscheduled sidebar (including drag from the overflow popover), a focused fix for an empty-database first-run condition, and a strict subtask-containment rule for calendar views. Everything in v0.3.11b1 and v0.3.11b2 still applies — see [v0.3.11b1](v0.3.11b1.md) for the full feature set and [v0.3.11b2](v0.3.11b2.md) for the b2 deltas. This page covers only what changed between b2 and b3.

## ⚠ macOS Sequoia (15.x) and later — first-launch note

Same as b1 and b2: the DMG is ad-hoc signed, so Sequoia and later block first launch by default.

**System Settings path:**

1. Try to open the app, get the block dialog, click **Done**.
2. Open **System Settings → Privacy & Security**.
3. Scroll to the Security section — *"pytodo-qt was blocked to protect your Mac"*.
4. Click **Open Anyway**, enter your password, click **Open** on the re-prompt.

**Command-line shortcut:**

```bash
xattr -rd com.apple.quarantine /Applications/pytodo-qt.app
```

macOS Sonoma (14.x) and earlier can still use the legacy right-click → Open path.

## Added

### Detail-panel subtask CRUD (commit `06f6c1f`)

The task detail panel now exposes a full subtask surface for top-level tasks: a `+ Add Subtask` button that stays visible whenever the current item is top-level (it opens a confirmation dialog, so it does not need an edit-mode safety gate), one row per direct child with a checkbox, a click-to-drill-down title button, and an edit-mode-gated delete glyph. When the current item is itself a subtask, a `← parent reminder` breadcrumb appears at the top of the panel and routes back to the parent on click; the add button is suppressed under the single-layer-nesting rule.

Five new signals (`subtask_add_requested`, `subtask_delete_requested`, `subtask_complete_toggled`, `subtask_selected`, `parent_navigation_requested`) feed `MainWindow`, which routes each action through the existing undo-command paths so panel-driven subtask edits round-trip the undo stack identically to edits made from the list, kanban, or calendar views. `set_item` gained an optional `todo_list: TodoList | None` parameter so the panel can enumerate children and resolve a parent's title.

### In-app notification banners (commits `5c33cc6`, `853db67`)

A new `NotificationOverlay` widget renders banners directly inside the application window with a stack manager that handles multiple concurrent notifications. The `_notify` helper now routes through this `NotificationManager` in parallel with `desktop-notifier`, so users see both an in-app banner and the system notification when the platform supports system delivery, and at minimum the in-app banner when the system path is blocked or rendered as the generic Sequoia ad-hoc placeholder.

### Bidirectional drag-and-drop (commits `3006dfa`, `cf4dbf0`)

- Drag a calendar bar back to the unscheduled sidebar to clear its `due_date`. The reverse of the existing drag-into-a-cell scheduling action.
- Drag from the `+N more` overflow popover that opens when a calendar cell holds more tasks than the visible-slot cap. Rows in the popover are now draggable (still single-click-to-edit; the drag only initiates after the press-and-move distance exceeds the system threshold), so an item pushed into overflow remains rescheduleable without first opening its editor.

## Fixed

### Calendar rendering

- **Equal-width cell slots (commit `a98200f`).** Every bar present in a cell — whether it begins in this cell or continues from a previous one — is allocated the same horizontal slot width. The previous "wide chip vs thin ribbon" split allowed continuing slices to claim disproportionate width and crowded out in-cell tasks.
- **Visible deviation zones (commit `b9f2dcb`).** Two-zone bars for completed tasks now render their early-surplus (completed before the planned end) and late-overflow (completed after the planned end) deviation regions with sufficient chroma and texture (BDiagPattern / FDiagPattern) to read as distinct from the base zone. The previous translucency-only treatment fell below the perception threshold at typical zoom levels.
- **Reinforced legend (commit `198d7a9`).** Legend state swatches enlarged and the legend now shares a label surface with the cell painter so the same wording reinforces the same color in both places. Supports the WCAG 1.4.1 redundancy requirement for users who cannot easily resolve the legend's two-green palette.
- **Drop-time forward-clamp (commit `806b64e`).** Dropping a bar onto a cell on today's column now anchors to the end of the hour and forward-clamps so the implied window origin is never before the current moment. Prevents "drop into the past" outcomes that produced spurious overdue states immediately after a reschedule.
- **Visibility guarantee (commit `8a02075`).** Every item with a `due_date` falling inside the visible week range now resolves to at least one cell — hour grid bar, all-day chip, or marker — across every supported metadata shape (timed, all-day, workback with estimate, pomodoro estimate, event window, subtask with sub-floor duration). A regression-test class enumerates the shapes so future edits cannot silently drop a case.

### Subtask containment in calendar (commit `dc42690`)

Subtasks no longer render as first-class entries in day, week, or month calendar cells, and no longer appear in the unscheduled sidebar. They remain fully reachable and editable through their parent task's detail panel. The previous behavior — showing scheduled subtasks alongside their parent in calendar cells — produced visual ambiguity where a subtask bar in an earlier time bucket than its parent read as an unrelated top-level task. The kanban board and list view continue to surface subtasks via their respective expand affordances; this change is scoped to the calendar widget.

### Active-list resolution after first-run sync (commit `6429ebc`)

A first launch into an empty database followed by a P2P sync that populates lists now correctly resolves the active list from configured state after the sync completes, instead of leaving the user staring at an empty list-selector UI.

## Known limitations

### macOS Sequoia 15.x + ad-hoc signing: notifications render as a generic placeholder banner

Carried unchanged from b2. The Sequoia-and-later notification path has a bundle-identity constraint that no runtime code can work around. The in-app banner introduced in this release is the workaround on this platform — title and body always render correctly inside the app window. Resolving the system-banner path requires Developer ID signing, which is deferred.
